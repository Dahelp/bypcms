# BYPCMS: проверка панелей и установочных пакетов — 7 ноября 2026

Следующий этап лицензирования описан отдельно в
[ACCEPTANCE-LICENSING-2026-11-07.md](ACCEPTANCE-LICENSING-2026-11-07.md).
Ниже сохранён результат первоначальной приёмки панелей и пакетов.

Проверки выполнены в репозитории `platform/`. Боевые клиентские записи не использовались:
Owner/Admin проверялись на отдельном локальном стенде, пакеты — на Apache 2.4,
PHP 8.2 и отдельном экземпляре MariaDB 10.4 на loopback-порту 3319.
Демо проверялось также на опубликованном demo.bypcms.ru в браузере.

## 1. Вход, навигация и формы

- Demo: вход по прямому URL редактора; SEO-настройки → Back с сохранением Title,
  названия и вкладки; новый и сохранённый материал → предпросмотр → Back/«Закрыть».
- Admin: заполнение новой страницы → Reload; список → Back; принудительное завершение
  серверной сессии → неуспешное сохранение → повторный вход → та же заполненная форма.
- Owner: те же проверки рабочей копии клиента; ошибка API 503 сохраняет форму и не
  превращается в просьбу войти; после восстановления API запись сохраняется в MySQL.
- Проверены общий выход между вкладками Owner/Admin, сохранение адреса назначения,
  отказ редактору в доступе к Owner и явная ошибка неизвестного раздела.
- CSRF: Apache преобразовывал нестандартный HTTP 419 в 500. Теперь сервер отвечает
  HTTP 403 с `details.code=csrf_expired`; клиент обновляет сессию и предлагает явный
  повтор. Изменяющие запросы автоматически не повторяются.
- Рабочие копии разделены по пользователю, адресу и форме; пароли, скрытые поля и файлы
  не сохраняются. Logout удаляет копии, успешное сохранение очищает копию текущего экрана.
  Свежий переход к созданию не подставляет предыдущую запись.
- Выход доступен также в настройках обеих панелей, включая мобильный экран.

## 2. Таблицы

В браузере Admin проверены выбор двух строк, смешанный общий чекбокс, подтверждение,
отмена, полный сбой API с сохранением выбора и успешный повтор. Результат: изменены
только выбранные строки, успешные строки сняты с выбора. В Owner проверен пустой
список работ с недоступным общим чекбоксом.

27 PHP-проверок массовых операций проходят, включая частичный сбой, транзакцию аудита,
защиту системных/родительских страниц, допустимые статусы и права Owner.
HTTP-проверка на MySQL дополнительно подтвердила частичный результат и неизменность
невыбранных записей. Фильтры, пагинация и каталог 1000+ файлов покрыты отдельными тестами.

## 3. Материал и медиа

В браузере проверены загрузка фото из редактора, применение обложки, ошибка обязательного
адреса без потери текста/фото, первое успешное сохранение с переходом на `record=ID`,
изменение сохранённого материала без сохранения → предпросмотр → Back.

Исправлено отображение HTML основного текста в предпросмотре: разрешённое форматирование
совпадает с редактором, исполняемые ссылки и обработчики событий удаляются.
При ширине документа 390 px проверены Owner, Admin и Demo; в предпросмотре Demo
ширина документа и scrollWidth равны 390, форматирование и возврат к форме работают.
Мобильная ширина задавалась настоящим iframe viewport локального стенда, поскольку
изменение viewport через инструмент браузера не применялось.

## 4. Реальные ZIP и установка

Сформированы ZIP Content, Business и Commerce через `build.download`, проверены записи
архивов на отсутствие runtime-конфигурации, приватных данных и каталогов Owner/Account.
Выполнена 51 проверка на реальных установках Apache/MySQL:

- чистая установка каждой редакции, соответствие manifest редакции и модулей;
- вход владельца, создание/изменение контента и чтение сохранённого текста отдельным HTTP-запросом;
- прямые публичные URL, HTTP 404 отсутствующего материала;
- HTTP 403 для `_core`, `_storage`, `_private`;
- доступность `/admin/` и всех её JS/CSS с собственного адреса установки;
- недействительный CSRF, выход, запрет повторной установки с заменой владельца;
- ошибка схемы на пустой БД → очистка созданных таблиц → успешная повторная установка;
- новая папка с существующей БД отклоняется без замены учётной записи.

Исправлены два дефекта пакетов: привязка JS/CSS к bypcms.ru и отсутствие index.html
в DirectoryIndex, из-за которого Apache не открывал `/admin/`. Исправление DirectoryIndex
применено и к конструктору, и к выдаче пакета покупателю.

При проверке публикации выявлено отличие document root поддомена от FTP-каталога
отдельного пакета. Ресурсы demo включены также в каталог `/demo` основной сборки,
чтобы оба варианта настройки хостинга обслуживали собственные JS/CSS.
Выкладка demo использует инкрементальный FTP-манифест без предварительного удаления
всего каталога. Финальный шаг CI проверяет реальные HTML/JS/CSS всех трёх панелей:
404 или HTML вместо ресурса завершают выкладку ошибкой. Эта проверка покрыта тестами.

## Что эта проверка не подтверждает

Это базовая приёмка панелей и установки, не сертификация CMS для продажи.
Полная работа платежей/доставки, лицензирование и активация, отправка писем,
обновление с резервной копией/откатом и соответствие всех девяти тем демонстрации
не подтверждены. Регистрация модуля в БД не доказывает работу его бизнес-сценария.
Эти пункты остаются обязательными до выпуска клиентской CMS.
