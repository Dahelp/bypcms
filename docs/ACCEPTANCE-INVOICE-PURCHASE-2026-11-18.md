# Приёмка покупки по счёту — 18 ноября 2026

## Область проверки

Полный путь покупки Content, Business и Commerce проверен на отдельных локальных установках: регистрация → заказ → принятый точный счёт → ручное подтверждение → письма → лицензия → авторизованное скачивание → установка полученного ZIP → активация ключа с проверкой домена и RSA-подписи.

Все покупатели, заказы, реквизиты, ключи и подтверждения искусственные. Платформа — `127.0.0.1:8019`, отдельные клиенты — порты 8121–8123, MariaDB — 3319 с отдельными БД `bypcms_purchase_20261118_*`. Лицензирующий сервер локальный; домены `.example.test` разрешаются в loopback только конфигурацией debug-стенда. SMTP — локальный TLS-приёмник с проверяемым тестовым сертификатом. Реальные платежи, API списания/возврата, письма через боевого провайдера и операции над клиентскими сайтами не выполнялись.

## Исправления

- При истёкшей сессии страница покупки/скачивания возвращала 401 и один текст без ссылки. Теперь направляет на вход с безопасным адресом возврата к той же покупке или архиву. Вход принимает этот маршрут; внешние и посторонние адреса по-прежнему отклоняются. Проверка владельца покупки и запрет доступа после возврата сохранены.
- Ошибка выдачи сохраняла подтверждённую оплату, но исходная причина терялась. В серверный журнал добавлены номер заказа, класс и причина ошибки; ключи BYP и 20-значные банковские счета удаляются до ограничения длины сообщения. Покупатель получает прежнее общее сообщение, без внутренних деталей.
- В TypeScript исключены `outputs`, `work`, `out`, `demo-dist`: вложенные тестовые установки и QA-worktree не должны попадать в компиляцию приложения.

Отдельно проверено отсутствие ключей, банковского счёта и SMTP-пароля в переданном письме; в ZIP нет приватных платформенных каталогов и секретов. ## Воспроизведение

Стенд использует схему существующих `tests/invoices.integration.php`, `tests/mail.integration.php`, `tests/commerce-mock.mjs`: отдельная платформа и три пустые клиентские БД, отдельные сессии/vhost, TLS-приёмник 8465 и его control API 8049. Приватные каталоги находятся вне DocumentRoot. В каталоге `outputs/purchase-acceptance-*` должны быть `site/`, `clients/{content,business,commerce}/`, корректная debug-конфигурация платформы и сопоставление тестовых доменов. На Windows нужен `OPENSSL_CONF` с конфигурацией PHP/OpenSSL.

```powershell
$env:BYPCMS_TEST_PHP='C:/xampp82/php/php.exe'
$env:OPENSSL_CONF='C:/xampp82/apache/conf/openssl.cnf'
node tests/invoice-purchase-journey.mjs outputs/purchase-acceptance-20261118
php tests/invoices.integration.php outputs/purchase-acceptance-20261118/site
node tests/invoices-http.mjs outputs/purchase-acceptance-20261118/invoice-result.json
php tests/mail.integration.php outputs/purchase-acceptance-20261118/site
node tests/mail-http.mjs outputs/purchase-acceptance-20261118/mail-result.json
```

Сквозной тест рассчитан на свежие клиентские БД и отказывается заменять уже установленный клиент. Helper ограничен указанной локальной платформой, её искусственными заказами и БД. Отчёт `journey-result.json` не содержит секретов; `journey-private.json`, ZIP и SMTP-wire остаются только в игнорируемом каталоге стенда. После проверки локальные серверы останавливаются.

Проверка после выкладки — только чтение: `scripts/verify-commerce-deployment.mjs` проверяет доступность кабинета, границы доступа, возврат после входа и allowlist. В боевой среде тестовые счета не создаются, оплата не подтверждается. Опубликованный неизменяемый клиентский выпуск 2.7.1 повторно не публикуется.
