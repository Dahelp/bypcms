# Настройки, почта и первоначальная загрузка разделов

## Исправления

Настройки подключений отделены от текущих операций:

- `/owner/?section=payments` — «Заказы и оплаты»: покупки, выдача, возвраты.
- `/owner/?section=mail` — «Почтовые уведомления»: очередь, ошибки и повтор отправки.
- `/owner/?section=settings&tab=payments` — «Настройки → Оплата»: ЮKassa и чеки.
- `/owner/?section=settings&tab=mail` — «Настройки → Почта»: SMTP и отправитель.
- `/owner/?section=settings` — основные настройки профиля/платформы.

Старые ссылки `payments&panel=connection` и `payments&panel=mail` распознаются без редиректа и без добавления записи в историю браузера. Ссылки из уведомлений, фильтры, пагинация и возврат из настроек ведут в соответствующий раздел. Сохранение каждой группы отправляет только её параметры и её секрет; оно не перезаписывает второе подключение.

CSS-правило полной ширины текстовых полей по специфичности перекрывало ширину checkbox. Флажок занимал строку, подпись сжималась до одного символа. Размер 18×18 закреплён отдельным правилом, подписи и удаление секрета получили нормальную компоновку; поле секрета и его флажок имеют отдельные доступные подписи.

Owner после получения bootstrap отрисовывал начальный `overview` до применения URL из эффекта. Теперь основной интерфейс появляется только после готовности маршрута. Admin получает выбранный раздел и редактор из одного состояния URL, поэтому при загрузке записи не появляется её список перед редактором. Demo сохраняет существующий барьер готовности маршрута. До готовности используется общий нейтральный экран загрузки, без содержимого другого раздела. Браузерная история и обычные ссылки сохранены.

## Приёмка

31 Node-проверка маршрутов, таблиц, API/черновиков и предпросмотра прошли. Новые проверки воспроизводят состояние Owner с готовыми данными и ещё не разобранным URL, начальную отрисовку Admin, старые ссылки и разделение сохраняемых параметров. Они включены в CI. TypeScript, ESLint изменённых общих компонентов и производственная сборка прошли.

В реальном браузере на изолированном стенде проверены: отдельные формы оплаты/почты; сохранение оплаты; ошибка SMTP host с сохранением введённого имени; исправление и повторное сохранение; checkbox удаления секрета без удаления; переход к заказам и браузерный «Назад»; старая ссылка на настройки; прямой вход в Admin → Настройки, Admin → Контент, demo → Страницы и переход к материалам.

На мобильном экране 390×844 внутренние размеры `clientWidth` и `scrollWidth` равны 375 px с учётом полосы прокрутки. Все три флажка оплаты имеют размер 18×18, подписи читаются строками. Доказательство сохранено в ignored `outputs/acceptance/payment-settings-mobile-fixed.png`.

Финансовые операции, подключение ЮKassa и реальная отправка почты для этой правки не выполнялись. Боевые настройки и секреты не изменяются публикацией. Результат штатной публикации и читающих проверок после неё сообщается в отчёте задачи.
