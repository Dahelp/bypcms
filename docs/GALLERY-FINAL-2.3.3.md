# Gallery 2.3.3: отмена, фильтры и Web Vitals

## Изменения

- Подтверждение отмены — обычная страница того же заказа (`?ref=…&cancel=1`) с кнопками «Да, отменить заказ» и «Оставить заказ». Маршрут не зависит от `confirm()` или JavaScript. Back возвращает тот же заказ, GET не отменяет его.
- Сервер повторно проверяет владельца, CSRF и состояние заказа. Повтор отменённого заказа безопасно завершается до обращения к оплате; оплаченный заказ нельзя отменить, требуется рассмотрение возврата. Отмена с начатой оплатой не освобождает товар до подтверждённого `canceled` провайдера.
- Исправлены верхняя граница цены 0 ₽ и поиск буквального «0». Некорректные параметры-массивы показывают ошибку без PHP warnings; сортировка нормализуется. Денежные границы сохраняют копейки, пустой ответ и ошибка не подменяются полным каталогом.
- Шрифты Gallery переведены без изменения набора символов из TTF в WOFF2: Cormorant 1 195 560 → 209 384 байт, Manrope 164 700 → 53 796 байт. Суммарная передача уменьшена на 80,65%. Исходные TTF и OFL сохранены. Preload добавлен только для фактически выбранных шрифтов, версия ресурсов — 2.3.3.
- Включаемая диагностика `?vitals=1` загружает закреплённую официальную GoogleChrome/web-vitals 6.2.3. LCP, CLS, INP и TTFB выводятся только в консоль (`[Gallery Web Vitals]`). Нет отправки данных, хранилища, пользовательских идентификаторов и содержимого форм. Без параметра эти два диагностических скрипта не загружаются. Лицензия Apache-2.0 передаётся также в разрешённом JSON-ресурсе обновления.

## Проверка отмены

1. Браузер: исходный остаток 12, оформление двух единиц → 10. Переход к подтверждению, «Оставить заказ» и Back сохраняют резерв. Подтверждение отмены → «Отменён», остаток 12, `stock_released=1`, платежей 0, одно уведомление. Двойное нажатие не увеличивает остаток; Back после завершения не показывает действующую отмену.
2. Браузер: оплата одной единицы начата на локальном mock → остаток 11. Возврат без оплаты и попытка отмены оставляют «Ожидает оплаты» и 11 единиц. После отмены на странице mock и серверной сверки → «Отменён», остаток 12. Повтор через Back не добавляет товар и не дублирует уведомление.
3. `tests/gallery-cancel-http.mjs`: 21 проверка с реальной QA-БД, в том числе конкурентные повторы отмены, CSRF, чужой заказ, отмена провайдером, повторный опрос, запрет отмены оплаченного и гонка начала оплаты с отменой. Остаток проверяется непосредственно в БД, а не только по надписи интерфейса.

Mock-кнопка отмены существует только в `tests/commerce-mock.mjs`. Она не моделирует несуществующий API отмены `pending` в боевой интеграции. Терминальное состояние mock не может быть повторным нажатием переведено из canceled в succeeded.

## Web Vitals: метод и границы вывода

Использована официальная библиотека, включая её расчёт INP по Event Timing, а не таймер выполнения обработчика и не TBT. Диагностический режим не добавляет визуальные блоки, которые могли бы стать LCP или изменить раскладку. Перед взаимодействиями ожидается завершение загрузки шрифтов и двух кадров. Затем проверяются меню/клавиатура, ввод поиска либо увеличение и закрытие фото.

Лабораторный мобильный профиль: viewport 390×900, CPU ×4, 1,6 Мбит/с вниз, 0,75 Мбит/с вверх, задержка 150 мс, кэш отключён. Desktop: 1440×1000 без искусственного замедления, кэш также отключён. Профили временные и сбрасываются после замера. Фактическая ширина проверяется в DOM.

Локальные измерения после оптимизации (один прогон каждого шаблона):

| Шаблон | LCP, мс | CLS | INP, мс |
| --- | ---: | ---: | ---: |
| Главная | 976 | 0,00075 | 48 |
| Каталог | 988 | 0,00042 | 32 |
| Товар | 1112 | 0,00023 | 48 |

После выкладки выполняются три повторения каждого шаблона в обоих профилях непосредственно на demo.bypcms.ru. Сырые результаты сохраняются в игнорируемом `outputs/gallery-acceptance/vitals-live-final.json`; это лабораторные сессии, а не 75-й процентиль реальных посетителей.

Ориентиры: LCP ≤ 2500 мс, CLS ≤ 0,1, INP ≤ 200 мс. Проверка популяции посетителей требует полевых данных: [Google Web Vitals](https://web.dev/articles/vitals). API PageSpeed Insights вернул 429 с исчерпанной публичной квотой; это сохранено в QA-доказательствах. Отчёт не присваивает несуществующий балл Lighthouse и не объявляет полевые CWV пройденными.

## Регрессии и поставка

Прошли Commerce/Gallery (168), фильтры (40), отмена (21), основной HTTP-путь (51), точные суммы/оплата (28), Business (49), Content (31), платформенная оплата (33), лицензии (49+10), массовые действия (27), пакет обновления (45). Production-сборка и проверка содержимого пакета выполняются перед push. Боевую публикацию подтверждают workflow, проверка ресурсов и замеры уже опубликованной версии.

Тестовые товары, контакты, ключи mock и БД изолированы от боевого сайта. Скриншоты подтверждения/результата отмены, `cancel-ui-after.json`, `cancel-http-result.json`, `filter-ui-results.json` и журналы CWV находятся в `outputs/gallery-acceptance/`. Реальных списаний, возвратов денег и писем внешним получателям не выполнялось.
