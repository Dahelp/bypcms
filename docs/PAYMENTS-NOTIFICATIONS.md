# Оплата лицензий и уведомления BYPCMS

Платформенная покупка: `/order/` → вход/регистрация `/account/` → сохранённый заказ → ЮKassa → проверка API → архив и ключ в кабинете. Продление годовой покупки доступно её владельцу в истории заказов. Суммы и допустимые модули рассчитывает сервер; включённые модули повторно не оплачиваются. Услуги с ценой «от» создают заявку на согласование без онлайн-списания. Это оплата лицензий самой платформы, не реализация интернет-магазина клиента.

## Подключение после подготовки магазина и почты

По умолчанию **оплата и SMTP выключены**. Откройте `/owner/?section=payments&panel=connection`.

1. Укажите Shop ID и тестовый ключ ЮKassa. Для подтверждённого статуса продавца — самозанятый без ИП — выберите ручные чеки «Мой налог» и подтвердите обязанность формировать/передавать их. Режимы кассы 54-ФЗ предназначены для других применимых сценариев. Пустое поле секрета сохраняет прежний ключ; удаление требует отдельного флажка. Сервер возвращает только признак наличия секрета. Тестовый режим на публичной платформе доступен только владельцу. Тестовая выдача помечена и выдаёт пробную лицензию на 7 дней; она не продлевает действующие лицензии.
2. Нажмите «Проверить подключение ЮKassa»: выполняется чтение API без создания платежа. Настройте в кабинете ЮKassa события `payment.succeeded`, `payment.canceled`, `payment.waiting_for_capture`, `refund.succeeded` на показанный HTTPS-адрес `/commerce/index.php?action=webhook`.
3. Настройте SMTP: STARTTLS:587 или SSL/TLS:465, логин, пароль, отправителя и email владельца. Запросите тестовое письмо, запустите обработку, проверьте очередь и фактический почтовый ящик.
4. Установите **cron каждую минуту**: `* * * * * php /ABSOLUTE/SITE/ROOT/_core/commerce-worker.php`. Точная команда для данного сервера показана в Owner. Выполнение через HTTP закрыто. После остановки обработки более 15 минут новые боевые платежи блокируются; заказы сохраняются. Каждый цикл сверяет до 2 платежей, выдаёт до 2 покупок и отправляет до 3 писем. При росте нагрузки нужны дополнительные/более частые циклы; параллельные отправители используют блокировки строк.
5. После проверки собственного магазина, чеков, почты и cron выберите боевой режим и боевой ключ. Нельзя менять магазин или режим, пока есть незавершённые/неопределённые платежи. На момент этой правки пользователь сообщил, что подключения ещё не подготовлены; реального платежа и доставки через его SMTP не выполнялось.

Секреты шифруются AES-256-GCM ключом приложения в приватном каталоге **вне DocumentRoot** (`UpdateRuntime::storage(...)/commerce/settings.json`). Они не входят в Git, публичный bootstrap, журнал действий, письма или ZIP клиента. При резервном копировании сохраняйте также ключ приложения и этот приватный каталог. Не меняйте `app.key` без миграции зашифрованных данных.

## Сбои и повторные действия

- Создание заказа идемпотентно по покупателю и operation ID. Состав и цена фиксируются перед оплатой. Повтор с другим составом не переиспользует уже созданный заказ.
- Платёжная попытка сохраняется **до** POST к провайдеру: неизменные payload и Idempotence-Key. Повтор pending использует прежнюю оплату; новую попытку разрешает подтверждённая отмена или однозначный отказ API. Сетевой сбой/500 не означает, что платежа нет.
- ЮKassa хранит идемпотентность 24 часа. После 23 часов неопределённую попытку не отправляем заново. Владелец находит ID в кабинете ЮKassa и запускает сверку ID в карточке заказа; сервер проверяет его через API. Ручной отметки «Оплачено» нет.
- Webhook и возврат браузера не являются доказательством оплаты. Сервер проверяет объект через авторизованный API, включая UUID, сумму в копейках, RUB, магазин, test/live, metadata заказа/попытки, succeeded и paid=true. Поддельный объект не выдаёт лицензию.
- Выдача не держит сетевой запрос оплаты внутри SQL-транзакции. При ошибке ZIP заказ остаётся оплаченным, владелец получает событие, выдачу можно повторить из Owner или cron. Повторная выдача и повторный webhook не создают второй ключ/продление.
- Годовая лицензия продлевается на год от более поздней из дат «сегодня»/окончание; при приостановке блокировка лицензии сохраняется. Модули не покупаются повторно. Пробная лицензия не становится действующей через продление.
- Письма создаются в durable outbox вместе с событием заказа. Ошибка SMTP не отменяет оплату. Безопасные отказы повторяются с задержкой, до 5 попыток. После передачи DATA и потери подтверждения — «Результат неизвестен», автоматического повтора нет. Прерванный отправитель с истёкшим lease также даёт неизвестный результат. Ручной повтор требует отдельного подтверждения возможного дубликата. Message-ID стабилен.
- «Принято SMTP» означает ответ принимающего SMTP, а не гарантированную доставку в Inbox. Ключи и пароли по почте не отправляются.
- В Owner доступны поиск и страницы заказов/писем, CSV выбранных строк, массовая сверка оплаты и повтор выбранных неотправленных писем с результатом по каждой строке. Неопределённые письма подтверждаются индивидуально.
- Старый `/account/review.php` на боевом сайте ведёт в новый раздел заказов; ручная выдача тестовой покупки закрыта. Исторические выданные тестовые архивы доступны прежнему покупателю.

## Проверка и границы

`php tests/commerce.test.php` — границы сумм, URL, UUID, заголовков и безопасные значения по умолчанию; включено в CI перед выкладкой.

`tests/commerce.integration.php` допускает только изолированный root с debug, URL `http://127.0.0.1:8019` и БД на 3319. Нужны подготовленные таблицы платформы и `tests/commerce-mock.mjs` (API на 8049, TLS SMTP на 8465), сертификат с SAN IP:127.0.0.1 в ignored `outputs/acceptance/smtp-cert.pem` и его ключ. Проверка не отключает TLS: стендовый CA передаётся cURL. Подмена API/SMTP возможна только через серверный debug-конфиг с loopback; Owner не задаёт эти адреса. Тесты используют отдельные аккаунты и фикстуры; не запускать их на рабочей БД.

`node tests/commerce-http.mjs outputs/acceptance/commerce-result.json` проверяет реальные HTTP-сессии, роли, CSRF, точный возврат после входа, недоступность чужих заказов и повтор создания.

`node scripts/verify-commerce-deployment.mjs` — безопасная проверка публикации: публичный каталог, закрытые настройки/CLI и форма входа. Не создаёт заказов и платежей.

Настоящее списание/возврат в магазине пользователя, чек «Мой налог», доставка его SMTP и обработка cron хостинга требуют подключения и отдельной приёмки. Реализованы ручное решение о полном/частичном возврате, сверка API и отзыв оплаченных прав: см. [REFUNDS-YOOKASSA.md](REFUNDS-YOOKASSA.md). Автоматическое одобрение обращений, спорные платежи и рекуррентные списания не реализованы и не имитируются.

## Публичная страница для анкеты подключения

`https://bypcms.ru/contacts/` содержит ФИО исполнителя, подтверждённый пользователем ИНН и контактную почту. Ссылка доступна в общем подвале публичного сайта, кабинете и карточке заказа/покупки. Банковский счёт физического лица и фото банковских реквизитов не публикуются. Номера ИНН/КПП банка не используются как реквизиты исполнителя.

На странице описаны реальный путь получения архива/ключа, отдельное согласование индивидуальных работ и способ обращения по оплате/возврату. Это информационная страница, а не утверждённая оферта.

Опубликованы условия покупки, получения и возвратов, политика данных и отдельное согласие в `/legal/`; обязательные подтверждения сохраняются сервером с версией документов. Пользователь подтвердил статус самозанятого без ИП и публичный телефон. Внешние шаги подключения и границы приёмки перечислены в [REFUNDS-YOOKASSA.md](REFUNDS-YOOKASSA.md).
