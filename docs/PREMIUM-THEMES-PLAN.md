# План полноценных премиальных тем BYPCMS

Основание: [аудит от 7 ноября 2026 года](PRODUCT-AUDIT-2026-11-07.md). Пользователь выбрал порядок: сначала по одной полноценной теме для Content, Business и Commerce, затем ещё шесть. Для первой тройки используем существующие имена Journal, Atelier и Gallery.

Это исходное техническое и продуктовое задание. Выполненные этапы описаны отдельно: Journal (Content), [Atelier 2.2.0](BUSINESS-ATELIER-2.2.0.md), [Gallery 2.3.0](COMMERCE-GALLERY-2.3.0.md). В документах этапов указаны фактические проверки и ограничения; визуальная приёмка Gallery ожидает доступа к браузеру.

## Что должно измениться

Каждая тема становится законченным клиентским сайтом со своей композицией, внутренними страницами и рабочим пользовательским путём. Полноценность включает не только вид первого экрана, но и контент, медиа, навигацию, поиск, формы или заказ, состояния ошибок и установленный на хостинге результат.

Тема поставляется в клиентском ZIP. Её выбор, бренд, меню, цвета, типографика и настройки сохраняются на сервере. Предпросмотр использует ту же модель данных и renderer, что опубликованный сайт. Переключение темы сохраняет контент и не требует правок ядра.

## Первая тема Content Journal

Направление: современное издание об архитектуре, культуре и дизайне. Сильная редакционная типографика с качественной кириллицей, разные масштабы историй, большие фотографии с осмысленным кадрированием, спокойные поля и явная иерархия. Главная выглядит как выпуск издания с редакционной подборкой, а не одинаковая сетка карточек.

| Страница | Состав и поведение |
| --- | --- |
| Главная | Редакционная история, разные форматы анонсов, рубрики, новые материалы, подборка редактора; все ссылки ведут в реальные записи |
| Все материалы | Список/сетка, рубрика, сортировка, пагинация; состояние отражено в URL |
| Рубрика | Собственное описание, лид-материал, список, хлебные крошки, пустая рубрика |
| Материал | Заголовок, лид, автор, дата, обложка, удобная колонка чтения, оглавление, изображения/галерея/цитаты/подписи, связанные материалы |
| Автор | Биография, фото, ссылки, опубликованные материалы автора |
| Поиск | Запрос в URL, результаты, подсветка/релевантность, отсутствие результатов, очистка |
| О редакции и контакты | Настоящий редактируемый контент и контактная форма при установленном forms; корректное состояние без модуля |
| Служебные страницы | 404, поиск с ошибкой, удалённый материал, защищённый preview черновика |

Путь приёмки: создать материал и рубрику → загрузить обложку из редактора → заполнить блоки и SEO → preview без потери ввода → опубликовать → найти в рубрике и поиске → открыть отдельную ссылку на телефоне. Редакционные даты, авторы и изображения принадлежат данным, не прописаны внутри темы.

## Первая тема Business Atelier

Направление: уверенный сайт дизайн-студии или архитектурного бюро. Выразительные кейсы, асимметричная композиция, крупная фотография/медиа, выразительная типографика, короткие ясные CTA. Доверие строится на управляемых проектах, команде и отзывах. Числа и награды не выдумываются: блок скрывается, если данных нет.

| Страница | Состав и поведение |
| --- | --- |
| Главная | Позиционирование, избранные кейсы, услуги, подход, команда/доверие при наличии, заявка |
| Услуги | Направления, описание, фильтр при необходимости, переход в услугу |
| Услуга | Задача и результат, этапы, связанные кейсы, цена/условия при наличии, форма с выбранной услугой |
| Проекты | Сетка с разными масштабами, фильтр по направлению, пагинация |
| Кейс | Контекст, задача, решение, изображения/галерея, результат, команда, следующий проект, CTA |
| О компании и команда | Реальная история и сотрудники; ссылки на специалиста/кейсы при наличии |
| Контакты и заявка | Контакты, согласия, валидация, ошибки/успех; заявка действительно появляется в CRM |
| Служебные страницы | 404, пустые списки, недоступный кейс, успешная отправка, ошибка с сохранением введённого |

Путь приёмки: открыть услугу → изучить кейс → отправить заявку с контекстом услуги → увидеть подтверждение сохранения → сотрудник открывает ту же заявку, назначает ответственного и меняет статус → письмо доставлено либо ошибка доступна для повтора. Нельзя показывать «письмо отправлено» только по нажатию кнопки.

## Первая тема Commerce Gallery

Направление: полноценный магазин предметного дизайна, мебели и света. Товарная фотография и коллекции, понятная цена/вариант/наличие, удобные фильтры, выразительные интерьерные истории. Визуальная чистота сочетается с заметными действиями покупки и ясными условиями доставки.

| Страница | Состав и поведение |
| --- | --- |
| Главная | Коллекции, подборки, товарные акценты, редакционная история, условия покупки; управляемые товары |
| Каталог и категория | Поиск, фильтры/диапазон цены, сортировка, количество результатов, пагинация и URL состояния |
| Коллекция/бренд | Описание, медиа, связанные товары и переходы |
| Товар | Галерея/увеличение, варианты, цена, наличие, количество, характеристики, доставка, связанные товары; отзывы только при рабочем модуле |
| Корзина | Сохранённые позиции, варианты/количество, удалить/вернуть, промокод, серверный итог, изменение цены/остатка |
| Оформление | Контакты, адрес, доставка, оплата, согласия, итог; сохранение заказа до перехода к провайдеру |
| Статус заказа и кабинет | Ожидание/оплачен/отмена/ошибка, повтор допустимой оплаты, список заказов и безопасный доступ к своему |
| Контакты, доставка, возврат | Настоящие условия продавца; ссылки доступны до оплаты |
| Служебные страницы | Пустой каталог/корзина, нет результатов, нет товара, товар закончился, платёж не подтверждён, 404 |

Путь приёмки: категория → фильтр → товар/вариант → корзина → доставка/промокод → сохранённый заказ → тестовая оплата → подтверждение сервером → статус/письмо. Отдельно: отмена, двойной клик, повтор webhook, изменение остатков, частичный возврат, ошибка почты. Финансовые операции не имитируются локальным изменением надписи.

## Общие требования к UX и качеству

| Область | Критерий приёмки |
| --- | --- |
| Композиция | У первой тройки разные главные и внутренние композиции под их задачи; нет повторяющегося общего hero со сменой цвета |
| Типографика | Лицензированные локальные шрифты с кириллицей; стабильная загрузка; заголовки/текст/метаданные читаются на телефоне и desktop |
| Медиа | Согласованный комплект реалистичных фотографий с правом использования, адаптивные размеры, alt/подписи, заданные пропорции, состояние без фото; без случайного повторения одной картинки |
| Контент | Осмысленные демонстрационные материалы, кейсы и товары; отсутствие шаблонных «здесь находится текст» и вымышленных коммерческих результатов |
| Навигация | Обычные ссылки на отдельные страницы; открытие в новой вкладке, прямой URL, Back/Forward, восстановление фильтра/позиции; modal только для локальных операций |
| Поиск и списки | Фильтр, сортировка и пагинация работают по данным сервера; пустой ответ, ошибка и повтор понятны пользователю |
| Изменение данных | Загрузка, защита от повторного действия, успешный результат, ошибка с сохранением ввода, отмена и повторная попытка |
| Доступность | Клавиатура и видимый focus, подписи полей/иконок, логичный порядок заголовков, достаточный контраст, управление диалогом, reduced motion |
| Мобильная версия | Реальные проверки 360/390/768 px и desktop 1280/1440; нет бокового переполнения, мелких кнопок, пропавших действий и зависимости от hover |
| Быстродействие | Размеры изображений заданы; нужные srcset/lazy loading, минимум JS для чтения страницы; измерения LCP/CLS/INP на итоговом сайте с реальными медиа, результаты сохраняются |
| SEO | Серверный HTML, правильный title/description/canonical/OG; sitemap/robots; закрытый preview; семантика и микроразметка из реальных данных |
| Поставка | Установка из выдаваемого ZIP, выбранная тема после нового входа, настройки и контент после обновления; возврат на предыдущую версию при сбое |

## Устройство поставляемой темы

Предлагаемый контракт реализации должен включать идентификатор, версию, совместимые редакции/модули, доступные шаблоны страниц, схему настроек, ресурсы и демонстрационные данные. Контракт нужно закрепить в коде и проверить при сборке; сейчас готового пакета девяти тем нет.

Данные темы, контент и исходные файлы разделяются. Смена дизайна не стирает материалы, заявки и заказы. Тема не содержит PHP из пользовательского произвольного upload и не обходит проверку прав модулей. Отсутствующий необязательный модуль скрывает его блок или показывает корректный fallback, а не неработающую кнопку.

Нужны единые общие механизмы медиа, SEO, формы, корзины, навигации и preview. Визуальные шаблоны при этом остаются самостоятельными. Дизайн не дублирует бизнес-логику оплаты или обработки заявок.

## Вторая очередь из шести тем

| Тема | Самостоятельное направление | Что отличает её от первой темы редакции |
| --- | --- | --- |
| Chronicle | Газетное аналитическое издание | Плотная редакционная иерархия, колонки, рубрикатор, длинное чтение; не Journal в другом цвете |
| Focus | Фотография и визуальное медиа | Галерейная подача, визуальные истории и подборки, иная сетка материалов |
| Corporate | Компания с несколькими направлениями | Разветвлённая структура, отраслевые решения, документы, команда и контактные точки |
| Mono | Авторская студия или независимый специалист | Типографическая композиция, сильный проектный портфель, короткий путь к заявке |
| Market | Магазин с большим ассортиментом | Плотная товарная сетка, заметный поиск, развитые фильтры, компактные карточки и навигация категорий |
| Luxe | Премиальный бренд и коллекции | Арт-дирекция, крупные визуальные истории, более камерная товарная подача, проверенные контрасты во всех состояниях |

Каждая тема второй очереди получает полный набор релевантных внутренних страниц, а не только изменённую главную. Общие серверные сценарии первой тройки переиспользуются.

## Очерёдность работы и контрольные результаты

1. Зафиксировать данные и страницы первой тройки, сделать прототипы ключевых путей и визуальное направление с реальным содержанием.
2. Исправить границы клиентской установки, renderer, медиатеку и базовый SEO; внедрить контракт темы.
3. Довести Journal до установки и реального опубликованного издания. Это первая проверка всей цепочки «панель → данные → тема → посетитель».
4. Довести Atelier вместе с формами/CRM и Gallery вместе с каталогом/заказом/оплатой. Не принимать дизайн отдельно от его основных действий.
5. Проверить все три на чистой установке, мобильном экране, прямых ссылках, ошибках и обновлении с откатом. Обновить demo и публичные обещания по фактическому результату.
6. Только после приёмки первой тройки перейти к Chronicle, Focus, Corporate, Mono, Market и Luxe.

Следующая реализация начинается с основы и Journal. Первая тройка считается завершённой после приёмки всех трёх клиентских сайтов; красивый предпросмотр одной главной не закрывает этап.
