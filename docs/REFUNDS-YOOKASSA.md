# Подключение ЮKassa: возвраты, права, документы

## Реализованный путь

Покупатель открывает оплаченный заказ в `/account/order.php?id=…`, пишет причину и отправляет обращение. Это сохраняет заявку и уведомляет владельца, **не возвращает деньги и не отключает лицензию**. Повтор обращения возвращает ту же открытую заявку.

Владелец открывает уведомление или заказ в `/owner/?section=payments&order=…`. В карточке видны обращения, суммы, операции и чеки. Владелец либо отклоняет обращение с объяснением, либо задаёт сумму и результат для оплаченных прав. Подтверждение отдельно показывает заказ, сумму и последствия; исходный фокус на «Отмена». Финансовых массовых действий нет.

Полный возврат, в том числе накопленный несколькими частичными, обязательно прекращает оплаченные права. Частичная компенсация может сохранять права, если владелец явно выбрал это решение. Для возврата продления снимается только срок этого заказа, а не первоначальная покупка и остальные оплаченные годы. Ручное изменение срока или старое продление без журнала требует сверки итоговой даты владельцем.

Одобренный возврат с отзывом прав временно блокирует серверную выдачу, обновления и активацию. `succeeded`, подтверждённый через API ЮKassa, завершает отзыв; `canceled`/однозначный отказ восстанавливает прежнее состояние. Неопределённый ответ сохраняет блокировку до сверки. Публичный сайт и данные покупателя не удаляются. Уже скачанный PHP-код нельзя удалить удалённо; существующая установка узнаёт об отзыве при проверке лицензии, с учётом ранее выданного кэша. Это не DRM.

Нельзя обойти возврат повторной выдачей, ручной активацией статуса в реестре, массовым изменением лицензий или старой ссылкой на ZIP. Операции проверяют центральный guard, покупателя, Owner-роль и CSRF.

## Сбои провайдера

Одобрение, неизменный payload и Idempotence-Key сохраняются **до** финансового POST. Повтор операции использует тот же ключ; webhook и cron не создают новое одобрение. Через 23 часа неизвестный результат не отправляется повторно: нужна читающая сверка ID из кабинета ЮKassa. API сверяет исходный платёж, магазин/режим, UUID, валюту и точную сумму.

`refund.succeeded` подключается вместе с событиями оплаты. Тело webhook не является доказательством: читается объект через авторизованный API. Сверка обнаруживает также возвраты, выполненные вручную в ЮKassa: полный отзывает права, частичный приостанавливает их до решения владельца. Cron обрабатывает до 2 незавершённых возвратов и сканирует до 1 оплаченного заказа за цикл (не чаще раза в 10 минут на заказ). При большом числе заказов увеличивайте производительность обработки; сверка из карточки немедленная. Не обещать мгновенное обнаружение пропущенного webhook на любой нагрузке.

## Чеки для подтверждённого статуса продавца

Пользователь подтвердил: самозанятый без ИП. В подключениях выбирается **«Самозанятый: чеки вручную в Мой налог»** и подтверждается обязанность формировать/передавать чеки. BYPCMS не отправляет фиктивный чек 54-ФЗ и не заявляет интеграцию с ФНС. Владелец формирует и передаёт чек в Мой налог, записывает HTTPS-ссылку из `lknpd.nalog.ru`/`npd.nalog.ru` в заказ. Покупатель получает ссылку в карточке и уведомление. После возврата появляется задача корректировки; владелец отдельно фиксирует её выполнение. Запись владельца не является проверкой ФНС.

Для другого продавца с кассой 54-ФЗ сохранены режимы ЮKassa/внешней кассы. Полный возврат использует исходный состав чека. Частичный возврат с точным распределением позиций для 54-ФЗ выполняется в кабинете ЮKassa и затем сверяется — автоматического распределения позиций в этом релизе нет. Не выдавать этот сценарий за интеграцию чека НПД.

## Страницы для анкеты

- `https://bypcms.ru/contacts/` — ФИО, ИНН, подтверждённый статус, email, телефон. Личный счёт и фото банковских реквизитов не опубликованы.
- `https://bypcms.ru/legal/offer/` — условия лицензии, цена в заказе, получение, поддержка.
- `https://bypcms.ru/legal/refunds/` — обращение, рассмотрение, деньги и прекращение прав.
- `https://bypcms.ru/legal/privacy/`, `/legal/consent/` — политика и отдельное согласие.

Публичные документы версионируются JSON-архивом; регистрация требует отдельного, изначально не отмеченного согласия. Оформление требует двух отдельных флажков: оферта и персональные данные. Сервер фиксирует версию, SHA256 точного текста, время, IP и User-Agent. Старый неоплаченный заказ требует подтверждения до оплаты. Исторический оплаченный заказ не теряется из-за отсутствия новых флажков. Новые документы не заменяют сохранённую версию старого заказа.

## Что остаётся вне кода перед включением реальных платежей

1. Завершить анкету и договор ЮKassa, получить Shop ID и ключ; вводить секрет только в Owner, не в чат/Git.
2. Подключить SMTP для `hello@bypcms.ru`, проверить принятый сервером тест и фактическое получение письма; проверить DNS/SPF/DKIM у почтового провайдера.
3. Настроить cron хостинга и webhook, проверить их реальный запуск. Ручной цикл не доказывает работу расписания.
4. Сформировать реальный чек Мой налог по проверочной покупке, проверить отправку и корректировку при согласованном возврате. Реальные деньги проверяет владелец.
5. Перед продажей сверить готовность каждой продаваемой редакции/модуля с публичным описанием. Этот релиз реализует **платежи лицензий платформы**, а не универсальный модуль эквайринга интернет-магазина клиента. Нельзя объявлять клиентский модуль платежей готовым только на основании этой приёмки. Существующие рекламные описания более широких возможностей не являются доказательством их реализации.
6. Проверить реальные условия хостинга/хранения персональных данных и применимость уведомления оператора Роскомнадзору. Код не подтверждает местонахождение серверов или исполнение обязанности оператора.

Оплата и SMTP на боевом сайте по умолчанию выключены. Отсутствующие аккаунт/ключи/SMTP не подменяются тестовыми боевыми подключениями. ЮKassa принимает решение о подключении самостоятельно.

## Развёртывание и возврат версии

Новая схема добавляет таблицы через CREATE IF NOT EXISTS, не удаляя старые заказы/лицензии. Перед восстановлением БД необходимо сверять фактические платежи и возвраты ЮKassa: **откат БД не отменяет движение денег**. После первых реальных возвратов не возвращать старый runtime без guard отзыва прав; сохранять журнал и применять исправление вперёд. Приватные настройки и app.key не перезаписывать.
